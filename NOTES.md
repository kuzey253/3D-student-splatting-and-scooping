# Mip-SSS: deviations from the README

Every departure from the handoff README (`../ReadMe.md`), with the reason. Newest last.

## M1 (2026-10-20)

1. **SSS has no fixed 2D dilation** (README M0.2, M2.1). The `+0.3` is commented out in `forward.cu:112-114` and `backward.cu:197-204`. M2 will add the 2D filter rather than replace a dilation.
2. **"Core" is defined as T ≥ 1e-3** for the accuracy test, because the README doesn't define it. The study also reports the renderable core, T ≥ 1/255: SSS skips |alpha| < 1/255 and |o| ≤ 1, so smaller kernel values never render. The test asserts the stricter definition. Choosing between them is a gate decision for the user.
3. **Fixed grid upper end.** The README gives z_min ≈ −12 but no z_max. `z_max = 3` is used; the weight is below 1e-6 of its peak there for every ν ≥ 1.
4. **README adaptive grid extents.** The README doesn't give them. [c − 6w, c + 3w] is used, with c and w the mean and standard deviation of log λ under Gamma(ν/2, ν/2), as the README says.
5. **Mass test computes ∫T_mip exactly** (`mass_option_b`: 2π|Σ|^½ Σ_k ω_k/λ_k, or exactly 2π|Σ|^½ with a control variate) instead of summing on a large grid. For ν ≈ 1 the kernel decays as r⁻³, so the mass outside any feasible grid exceeds the 1e-3 tolerance. `test_mass_formula_matches_numeric_integral` checks the exact formula against brute-force integration to 1e-6.
6. **Accuracy-test reference.** The FFT reference covers up to a 60 px half-width. Deep tails are measured against the λ-integral reference instead, which matches the FFT to < 1e-9 relative wherever T ≥ 1e-6 (`test_fft_agrees_with_lambda_integral`).
7. **Extended ν sweep** {…, 50, 100, 300, 1000, 10⁴}. SSS clamps ν to [1, 10⁴] and initialises it at 100 in every config.
8. **Not adopted: the README's Gaussian fallback above `nu_gauss = 30`.** Its error is up to 1.5e-2 at ν = 30 and 4.5e-3 at ν = 100, and it gives ∂T/∂ν = 0. With SSS's ν = 100 initialisation that would freeze ν for every component. It is kept only as the `readme` candidate, for comparison.
9. **Not adopted: the fast-path threshold 10·s for every ν.** Option A's error at ρ = λ_min/s = 10 is up to 0.12 at ν = 1. Thresholds are measured per ν instead (`results/m1/shortcut_study.md`).
10. **Added, not in the README:**
    - Option A′, a curvature-matched shortcut;
    - control variates (Option A or A′ evaluated exactly, quadrature only for the residual);
    - three node rules: `adaptive_tail` (weight-matched centre and a tail extent from τ), `gauss` (a Gauss rule for the log-Gamma weight), and two-segment `gauss` (bulk plus left tail).

    All are configured through `QuadConfig`.
11. **Gauss rules have no ν gradient in M1.** Their nodes are computed in numpy, so gradcheck skips ν for them. Using one in CUDA would need its nodes tabulated over ν.
12. *(Superseded by 19.)* The 3D path didn't support control variates during the M1 study.
13. **Pinned upstream quirks; behaviour unchanged.**
    - SSS's ν gradient omits −½·ln(1+b/ν)·G (`backward.cu:592`), pinned by `test_sss_nu_gradient_drops_the_log_term`.
    - SSS's radius table is interpolated in reverse within each [n, n+1) (`forward.cu:243-282`), pinned by `test_sss_radius_matches_cuda_table`.
    - The centre-pixel skip (`base <= 0`) is not reproduced in the kernel reference; it only matters for CUDA parity (M4).
14. **The README's own spec fails its required tests.** Fixed grid, K = 8, Gaussian above 30 fails accuracy (0/35), mass (0/7) and reduces-to-SSS (0/25); see `results/m1/REPORT.md`. The failures were reported, not loosened, and the final candidate was left to the gate.

## Gate after M1 (2026-10-20, decided by the user)

15. **Accuracy criterion changed by the user.** The README's "relative error ≤ 1e-3 in the core" is replaced by:
    - max alpha error ≤ 1e-3 against the exact filtered kernel over the whole domain, at |o| ≤ 1;
    - exact limits: s = 0 gives SSS, and ν → ∞ gives Mip-Splatting;
    - exact mass for the 2D filter.

    The agent did not relax this tolerance on its own; this is the user's decision at the gate. Relative error is still reported by `scripts/quad_study.py`.
16. **Chosen design** (`mip_sss/design.py`):
    - Option B: `adaptive_tail` with τ = 1/255, K = 12, an extent of ±3 widths, and the Option A control variate.
    - Fast path: Option A wherever λ_min(Σ)/s ≥ ρ(ν), using the table in `mip_sss/fastpath_table.py` (generated by `scripts/fastpath_table.py`, ε = 1e-3, aspect ratios up to 1:64).
    - No Gaussian fallback. The table sends every component with ν ≥ 300 to Option A, which depends on ν, so ν always has a gradient.
17. **The test suite now targets the design.**
    - Limits are asserted at ≤ 1e-12, since they are exact by construction.
    - Mass is checked by brute-force integration, to 1e-6.
    - Accuracy is max abs ≤ 1e-3 against the FFT reference for the whole extended ν sweep, and against the λ-integral for deep tails, random fast-path components and the 3D path.
    - The per-candidate tests were removed. The comparison remains in `scripts/quad_study.py` and in `results/m1/REPORT.md`.
18. **Removed `dlogw_dnu_fixed`** (the README's closed-form ∂ω/∂ν). It holds only for a ν-independent grid; the chosen grid moves with ν, as README step 4 anticipated. The CUDA backward must include ∂z_k/∂ν through ψ'(a) and ψ''(a). Autograd on the reference is the ground truth for that.
19. **3D path.**
    - Control variate: `option_b_3d` now supports one, using `option_a_3d` (Mip's 3D det ratio, projection, then 2D Option A). Both limits stay exact.
    - Fast path: Option A requires both λ_min(Σ3)/σ3² ≥ ρ(ν) and λ_min(M(Σ3 + σ3²I)Mᵀ)/s ≥ ρ(ν). The 2D table is reused for the 3D ratio; that rule is validated by the tests (including thin splats), not derived.
    - Mass: the 3D filter does not preserve projected 2D mass, in Mip-Splatting either, so "exact mass" applies to the 2D filter only.
20. **The fast-path table has a 10% safety margin.** Entries require error ≤ 0.9e-3 on the derivation grid, to cover shapes and sizes between grid points. As a result, Option A is accepted at every size from ν = 400, not ν = 300 as recommended at the gate. At ν = 300 its worst error on the grid is 9.8e-4, only 2% under the limit. Between 300 and 400 it is used for components with λ_min/s ≥ 5.6.
21. **M0 analysis tooling** (`mip_sss/analysis.py`, `scripts/m0_component_stats.py`) reads a trained model's PLY and `cameras.json` on CPU and reproduces SSS's activations, EWA projection and tile rectangles. Its cost figure is an estimate: transcendentals × tiles × 256, ignoring sorting, memory traffic and early termination.
22. **Build-only edits to SSS's CUDA sources, for the G4 image (torch 2.11, CUDA 13).** All are mechanical and leave the compiled arithmetic unchanged:
    - `Tensor::data<T>()` → `data_ptr<T>()`, 53 calls in `rasterize_points.cu` and `spatial.cu`. The two accessors are identical; `data_ptr` also exists in SSS's original torch 1.13.
    - `#include <cstdint>` in `rasterizer.h` and `rasterizer_impl.h`, for `uint32_t`.
    - `#include <cfloat>` in `simple_knn.cu`, for `FLT_MAX`.

    These were applied before the first build to avoid failed builds on a billing VM. The dry run confirms whether they suffice.
23. **M0 Colab runner** (`scripts/colab/`), following the user's Colab GPU runbook:
    - The runner packages the working tree and records its git state on the VM.
    - Training runs as a detached process. Status is checked with separate short `colab exec` calls, so nothing is sent into a streaming job.
    - Every remote step answers with `M0_<STEP>=OK|FAIL`, and every phase checks its output files, because `metrics.py` swallows its own errors.
    - Only small results are brought back.
    - The runner never starts or stops the VM.

## M2: 2D Mip filter in CUDA, Option A (2026-10-27)

25. **No dilation to replace** (see 1). The filter is added in `preprocessCUDA` right after `computeCov2D`: Σ′ = Σ + sI and opacity × sqrt(|Σ|/|Σ′|). It is guarded by `kernel_size > 0`, so with the flag off the arithmetic is SSS's, bit for bit. The radius comes from SSS's own rule applied to Σ′; the README allows this for Option A.
26. **Flag:** `--mip_kernel_size` (a pipeline parameter, default 0 = off; Mip-Splatting uses 0.1). It reaches the rasterizer as `TRasterizationSettings.kernel_size`. Caveat: `render.py`'s `get_combined_args` lets the command-line default (0.0) override the trained value, so filtered models must be rendered with `--mip_kernel_size` passed explicitly. The M0/M2 pipeline does this.
27. **Backward.** The conic gradient carries over unchanged (∂Σ′/∂Σ = I). The coefficient's gradient is added to dL/d(a, b, c) before the existing chain to the 3D covariance and the mean. The render kernel's gradient for the effective opacity o·coef becomes ×coef for the raw opacity. To do this the backward pass now receives the raw opacities: one more saved tensor and one more argument in the C++ binding.
28. **Parity method.** `mip_sss/raster_ref.py` re-implements the CUDA path in float64, including tile culling and SSS's ν gradient as written (`sss_nu_grad=True`). Locally it is checked against an independent pinhole projection plus the M1 kernels, to 1e-9. On the GPU, `scripts/colab/m2_checks.py` compares CUDA against it for s ∈ {0, 0.1, 0.3}, and compares filter-off against a build of the pre-M2 rasterizer (`OLD_REF`).
29. **Upstream finding: SSS damps covariance gradients of sub-pixel components.** `backward.cu` (inherited from 3DGS) turns conic gradients into covariance gradients with `denom2inv = 1/(det² + 1e-7)`. With 3DGS's 0.3 px² dilation, det² ≥ 0.008 and the epsilon never mattered. SSS removed the dilation, so for components below about 0.13 px, det² falls toward 1e-8 and their covariance gradients shrink. The first G4 dry run caught this: unfiltered (s = 0) covariance-gradient parity was off by up to 1.0e-3, and every filtered case passed. With the epsilon reproduced in the reference (`sss_conic_grad=True`, like `sss_nu_grad`), the s = 0 error drops to 3.4e-5 with the 1e-4 tolerance unchanged. The 2D filter removes the effect (det ≥ s²). Left as is in the flag-off path, since plain SSS must stay bit for bit.

## M3: 3D smoothing filter, Option A (2026-10-27)

30. **Applied in Python, as Mip-Splatting does.** Σ3 + σ3²I = R(S² + σ3²)Rᵀ, so the filter only changes the scales. The opacity is multiplied by sqrt(∏s² / ∏(s² + σ3²)), which is Option A in 3D for the t kernel. The CUDA rasterizer is unchanged. The flags are `--mip_filter_3d` (default off) and `--mip_filter_3d_variance` (default 0.2, Mip-Splatting's value). With `compute_cov3D_python` the filtered scales are used too; upstream Mip-Splatting leaves the filter out on that path.
31. **σ3 comes from `mip_sss.filter3d`** (ported from Mip-Splatting and tested in M1), via `NTModel.compute_3D_filter`. It is computed before training, right after every relocation step (README M3.2), and otherwise every 100 iterations until 100 before the end (Mip-Splatting's schedule). Mip-Splatting stops all updates 100 iterations before the end only because its densification ends at 15k; SSS relocates until 25k, so short runs relocate up to their last iterations, and recomputing after each relocation keeps σ3 aligned with the components. The getters raise if σ3 is stale.
32. **`filter_3D` is saved as an extra PLY attribute** when it exists, and loaded if present; it is not recomputed at test time, as in Mip-Splatting. Without the filter the PLY format is unchanged.
33. **Not yet (M5):** relocation, the opacity/scale regularizers and recycling still use the raw opacity and scale. `m0_component_stats.py` still analyses the unfiltered covariance.
34. **Upstream finding: SSS's float32 scale/rotation path exceeds the README's 1e-4 parity on very elongated components.** M2 tested the precomputed-covariance path; M3's checks are the first to use `scales`/`rotations`. Against a float64 reference, with the 3D filter off, the scale gradient of one component with scales 0.75/0.035/0.045 is off by 4.7e-4 (rotation 1.4e-4); every other quantity is within 1e-4. With the filter on, the same component's errors are about the same (1.5e-4 / 1.5e-4), so the filter adds nothing. The M3 checks therefore test M3's own code (the Python getters and their autograd chain) exactly against the CUDA rasterizer, and report the absolute float64 numbers without gating on them. If M4's CUDA parity needs 1e-4 on such components, SSS's `computeCov3D` backward would have to change; that path is plain SSS, so it is left as is.
35. **Float32 decision flips.** In 1 of 12 M3 cases a single pixel changes a discrete decision (an alpha or tile threshold) between float32 and float64, which shifts that component's gradients by up to 5e-3. Such cases (1–3 pixels off by > 1e-3) are reported and not scored; more than two per run fail. The filter values likewise have 1 point in 182,686 that sits on a camera's 15% visibility margin and flips in float64; at float32 precision every value matches to 2.7e-7.
36. **Float32 sensitivity of SSS's gradients for needle-shaped components.** In the M3 checks, a component with scales 0.75/0.040/0.049 has a rotation gradient that moves by ~1e-3 of its own size when its scales change by 1–2 ulps in random directions (about the long axis its rotation is nearly undetermined). The filtered model and the same model with σ3 folded into its parameters differ by exactly such ulps: the getters match the float64 formulas to < 2e-7. The wiring check therefore compares gradients against max(1e-4, 2 × the measured change from random ±1-ulp perturbations of the same scene) — the noise of the identical computation, as in M2's flag-off comparison against atomic-add noise.

## M4: Option B in CUDA (2026-10-27)

37. **Option B mode carries the 3D filter inside the quadrature.** On CPU (M4 prep), applying σ3 as a scale change before the quadrature (M3's way) leaves an alpha error of 0.17 on S1, against 3.2e-4 when each node gets its own 3D filter: cov2_k = Σ2/λ_k + σ3²TTᵀ, with c3_k from Σ3's invariants. So with `--mip_option_b` the Python 3D filter is off (`t_renderer`), and σ3 goes to the rasterizer as a per-component `filter_3d` tensor. Without `--mip_filter_3d`, σ3 = 0. The flag is a pipeline parameter like the others (render with it passed explicitly, see 26).
38. **Two modes per component, decided in `preprocessCUDA`.** A fast-path component (ν-aware ρ table, λ_min(Σ3) ≥ ρσ3² and λ_min(Σ2f) ≥ ρs) renders hp·t(covp) through SSS's own kernel and backward, with effective opacity o·hp: Option A in 2D and 3D. Its ν gradient and conic damping are therefore SSS's (see 29, and M2's `sss_nu_grad`), and the float64 reference reproduces them. An Option B component renders the K = 12 adaptive_tail quadrature with the Option A control variate, T = hp·t(covp) + Σ_k (g_k − h_k), with exact gradients.
39. **Node buffer.** `preprocessCUDA` flags Option B components, an exclusive scan gives each one a slot, and `preprocessOptionBCUDA` fills it: 203 floats (11 header + 12 nodes × 16, `mip_optionb.h`). The backward pass reuses it and adds 9 per-component accumulators (dL_dB, P × 9) filled by atomics in the render backward, then chained to dL/dcov3D and dL/dmean3D in `computeCovOptionB`. With the flag off, none of this is allocated or launched, and `computeCov2DCUDA` runs as before.
40. **Radius.** An Option B component's radius is the larger of SSS's rule on covp and an alpha-safe bound: every one of the 2K + 1 terms is below 1/255 / (2K + 1) outside it (closed form for the t term, Gaussian tails for the g_k and h_k). `raster_ref.optb_radius_bound` is the same rule in float64.
41. **Host checks before the GPU.** `mip_optionb.h` compiled as host C++ matches `optionb_staged.py` (float64) to ≤ 1.4e-5 relative (value, ∂/∂d, ∂/∂cov3D, ∂/∂T, radius) over 6 cases × σ3 ∈ {0, 0.004} × ν ∈ {1, 1.5, 3, 30, 150}. The exception is ∂/∂ν at ν = 150: off by 1.2e-3 to 6.5e-3. Running the staged Python itself in float32 gives the same errors to two digits, so this is float32 cancellation in the formulation (at ν = 150 the ν gradient is ~20× smaller than at ν = 30 and comes from differences of the g_k and h_k terms), not a transliteration error. The parity scenes' Option B components have ν ≤ 30 (ν ∈ {500, 5000} always take the fast path), so they do not exercise it; if ν ∈ (30, 400) needs 1e-4 on ∂/∂ν, the ν-derivative terms would have to be computed in double or rearranged.
42. **M4 checks** (`scripts/colab/m4_checks.py`, runner flag `M4CHECKS=1`): CUDA vs `raster_ref.rasterize_option_b` (float64) on 12 random scenes (σ3 off and on, 22–29 Option B components each), image and gradients at 1e-4 with the flip policy of 35; and SSS's `render()` in Option B mode on an NTModel (scales/rotations path), image at 1e-4 and gradients finite (gradients reported only, see 34/36). Flag-off parity is M2's and M3's suites, with `OLD_REF` set to the M3 commit.
43. **NaN gradients in Option B without the 3D filter (first G4 run), and the float32-safe forms that fix them.** `train_s01_ob` (s = 0.1, `--mip_option_b`, σ3 = 0) stopped at iteration 3860 of 7000 on SSS's NaN guard (`grad_means3D`). The run with the 3D filter and the checks were fine. Two terms of the first version are undefined in float32 for degenerate components, and only at σ3 = 0:
    - ∂log hp/∂D was formed as ½(1/D − 1/det3f). At σ3 = 0, det3f = D and the true value is 0, but for a flat component (det Σ3 = (s1s2s3)² below 2.9e-39) both reciprocals overflow and give ∞ − ∞. The per-node ∂log c3/∂D had the same form.
    - log c2_k took det(Σ2/λ_k) from separately rounded entries. For a nearly degenerate footprint, it can come out ≤ 0 even though det Σ2 > 0 passed the check. Such footprints are common: in the trained `train_s01_3d` model, about 30,000 visible pairs at full scale have λ_min(Σ2) < 0.001·s, and 3% of components sit at ν = 1, which is always Option B. With σ3 > 0, the σ²TTᵀ term keeps every node positive-definite.

    Fix (same math, only the arithmetic changes): the D gradient is carried as D·∂/∂D (bounded, in [0, ½]), and the chain applies Σ3⁻¹ as adj/D entry by entry. The 3D terms go through e = det3f − D and L3_k = λ³det3_k = D + e3_k: log c3 = ½(log D − log L3), and ∂log c3/∂λ = −½(σ²m + 2λσ⁴tr + 3λ²σ⁶)/L3, with no cancellation. At σ3 = 0 they are exactly zero and D is not used: c3 ≡ 1, log det cov2_k = log det Σ2 − 2 log λ_k, and cov2_k⁻¹ = λ_k Σ2⁻¹. So a flat component is no longer dropped there when its rounded D comes out ≤ 0 (SSS keeps it too); with σ3 > 0, D ≤ 0 still skips it, since its 3D-filtered peak is ~0.

    The staged Python, `direct()` and the fast path of `raster_ref` follow the same forms. The autograd tests pass unchanged. A new test, `tests/test_optionb_header.py`, compiles `mip_optionb.h` as host C++ and checks it against the staged Python: ≤ 1e-5 on values, ≤ 1e-4 on gradients, for ν ≤ 30. It also renders 1,500 random degenerate components (flat, needle, edge-on; σ3 = 0 and > 0; ν = 1) and checks that every value and gradient is finite whenever the component would be drawn. On that stress set, the first version gave NaN values in 3 drawn cases and NaN gradients in 34; this version gives none.
