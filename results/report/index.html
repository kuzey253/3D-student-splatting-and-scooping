Anti-aliased Student-t splatting (Mip-SSS)

Student Splatting and Scooping (SSS) renders scenes with Student-t components that have learnable tails. Like 3D Gaussian Splatting, it aliases when the camera zooms out. This project adds Mip-Splatting's two anti-aliasing filters to the t kernel, verifies every step against float64 references, and is now measuring the effect on Mip-Splatting's multi-scale benchmark.

§1

The problem: sub-pixel components alias

SSS renders each component through the 2D kernel below, with peak value 1 at the projected centre μ, a 2D covariance Σ and a learnable degree of freedom ν (ν = 1 is the Cauchy distribution; ν → ∞ the Gaussian).

SSS kernelT(u) = [ 1 + dᵀΣ⁻¹d / ν ]−(ν+2)/2,   d = u − μ,   α = o · T(u)

The image samples this kernel at pixel centres. A component narrower than a pixel can land between samples and vanish, or flicker as the camera moves; zooming out makes most components sub-pixel. Mip-Splatting fixes this for Gaussians with a 2D screen-space filter (convolve with a Gaussian of variance s = 0.1 px², the pixel's footprint) and a 3D smoothing filter that bounds each component's size by the training cameras' sampling rate. For a Gaussian both convolutions are closed-form. For a t kernel they are not: T ⊛ 𝒩(0, sI) is no longer a t.

§2

Method

2.1 The 2D filter on a t kernel

The README of this project proposed two ways to filter a t kernel.

Option A treats the filtered kernel as another t on the widened covariance, and scales the opacity so the peak drops the way a Gaussian's would. It is one determinant ratio per component, exact at s = 0, and preserves mass. Its tails are too heavy for sub-pixel components, because a convolved t is not a t.

Option ATA(u) = √(|Σ| / |Σ′|) · [ 1 + dᵀΣ′⁻¹d / ν ]−(ν+2)/2,   Σ′ = Σ + sI

Option B is exact in the limit. SSS's peak-1 t kernel is a scale mixture of peak-1 Gaussians, and each Gaussian can be filtered exactly. A quadrature over the mixing variable λ turns this into K filtered Gaussians:

scale mixtureT(u) = Eλ ~ Gamma((ν+2)/2, rate ν/2) [ exp(−½ λ dᵀΣ⁻¹d) ]   ≈   Σk ωk gk(u),   gk = √(|Σ/λk| / |Σ/λk + sI|) · exp(−½ dᵀ(Σ/λk + sI)⁻¹d)

The design uses K = 12 nodes on an adaptive_tail grid in z = log λ (closed-form in ν through the digamma and trigamma functions, extent ±3 widths, left end set so the grid resolves kernel values down to τ = 1/255), with Option A as a control variate: the quadrature only has to integrate the difference between the exact and the Option A kernel. The residual has zero mass and vanishes at s = 0, so mass and the SSS limit are exact for any K.

Option B, as renderedTB(u) = TA(u) + Σk ωk ( gk(u) − hk(u) ),   hk = the Option A integrand at node k

2.2 The 3D smoothing filter

Mip-Splatting bounds every component by the highest sampling rate any training camera has for it: σ3 = √0.2 · depth / focal, with depth the smallest over the cameras that see the point. With the filter on, the 3D covariance becomes Σ3 + σ3²I and the opacity is scaled by √(∏s² / ∏(s² + σ3²)), Option A in 3D. Under Option B the 3D filter enters each quadrature node before projection, covk = Σ2/λk + σ3²TTᵀ + sI, which is required: the scale-change shortcut leaves an alpha error of 0.17 on one test case against 3.2 × 10⁻⁴ per node. σ3 is recomputed before training, after every relocation and every 100 iterations, and stored in the PLY.

2.3 The hybrid: Option A where it is accurate, Option B elsewhere

Option B costs 24 exponentials and one power per pixel against one power for SSS, so it runs only where it is needed. M1 measured, for each ν, the smallest size ratio ρ = λmin(Σ)/s from which Option A stays within 10⁻³ of the exact kernel (Fig. 4b), with a 10% safety margin and aspect ratios up to 1:64. 2.4 Integration with SSS's training

  • Relocation on effective parameters (--mip_relocate_effective). SSS replaces dead components by copies of live ones and rescales their opacity and scale so the copies composite like the original. With the 3D filter on, the rendered opacity is o·coef(s, σ3), so relocation now runs on that, and writes back the raw opacity that renders the relocated one. The scale rule stays SSS's (a logged deviation: writing back an effective scale is infeasible below about 0.36 σ3).
  • Filtered scale regularizer (--mip_reg_filtered): SSS's scale penalty sees √(s² + σ3²), so it stops shrinking axes already below the filter.
  • SGHMC unchanged, as the README requires.
  • Diagnostic --mip_exact_nu_grad: gives fast-path components the exact ν gradient, which SSS's backward does not compute (it drops −½·ln(1 + b/ν)·G).

Every flag defaults to off. With all of them off the code takes exactly SSS's arithmetic.

The accuracy criterion was changed once, by the user at the M1 gate (NOTES 15): the README's "relative error ≤ 10⁻³ in the core" needs K = 32 nodes, while "max alpha error ≤ 10⁻³ over the whole domain, with exact limits and exact 2D mass" holds at K = 12. Relative error is still reported.

GPU work runs on Colab through a runner that packages the working tree, records the git state and image versions, trains in a detached process polled by short separate commands, and answers every remote step with an explicit OK/FAIL line. Each GPU session starts with a 1000-iteration dry run of the exact configuration.

Three float32 hazards and one root cause were found this way in M4: forward, slot-fill and backward kernels each recomputed det Σ2 in float32, and for a disc seen almost edge-on they disagreed in sign, so the backward computed 0·∞. A NaN capture on the GPU, replayed on the CPU, located it; later kernels now reuse the forward's determinant (NOTES 43–47).

M2–5

Training-resolution sanity: no regression, no gain

Every milestone trained Tanks & Temples train for 7000 iterations (cap 1.1M components) and evaluated at the training resolution. The filters are not expected to help there; these runs check that training stays stable and quality does not drop. Each point is a single stochastic SGHMC run.

M4–5

Why ν drifts to 1 under Option B

M4's Option B runs ended with about 30% of components at ν = 1, against 3% for the fast path alone, which made Option B 4–5× slower to render. The hypothesis (NOTES 52): Option B components get the exact ν gradient, while fast-path components get SSS's, which drops the term −½·ln(1 + b/ν)·G. M5 tested it with a flag that gives every component the exact gradient.

M5

How far relocation drifts from the filtered kernel

Relocation replaces one component by N copies at the same place, whose composite should render like the original: αnew(u) = 1 − (1 − o′K′(u))N against αold(u) = oK(u). SSS derives o′ and the scale factor for the unfiltered t. The script below measures the worst |αnew − αold| on a pixel grid for 5 shapes × ν ∈ {1, 100, 3000} × o ∈ {0.3, 0.9} × N ∈ {2, 4}, with σ3 = √0.2 px and s = 0.1 px².

M6

Zoom-out pilot on Blender lego

Protocol. Mip-Splatting's single-scale-train, multi-scale-test setting: train on the full-resolution (800 × 800) Blender images, test on the 200 test views at 1/1, 1/2, 1/4 and 1/8 resolution (box-downsampled, focal length halved per scale, Mip-Splatting's converter run verbatim). 30,000 iterations, white background. Mip-Splatting was rerun at commit dda02ab with the arguments of its own protocol scripts (kernel size 0.1), with build-only patches. All runs are scored by the same per-scale script (SSS's PSNR, SSIM, LPIPS-VGG); both projects' own metrics.py average all scales together.

Data. The Blender set came from a public mirror. Read remotely, its 6,425 files matched a second, independent mirror in name, size and CRC32; the VM checks a manifest digest before use.

Configurations. SSS (plain, cap 300k), Mip-Splatting, SSS + Option A (2D and 3D filters, effective relocation), SSS + Option B. One run each, on one A100 session (the G4 was unavailable).

Pilot, not benchmark. One scene, one stochastic run per configuration, the SSS cap provisional (300k, chosen before Mip-Splatting's count was known; it ended at ). The Option B run was lost: at the last collection it was at iteration of 30,000 when the VM disappeared.

§10

Open questions and next steps

  • Option B on lego is unmeasured. The pilot's most important arm was lost twice to Colab. A rerun needs either a stable VM or Option B first in the run order.
  • ν drift under the filters (Fig. 15). Which part moves ν on Blender (2D filter, 3D filter, effective relocation, random initialization), and whether it costs quality at other scales, is open. It also decides Option B's cost.
  • Which ν gradient Option B should use (M5). Keeping the exact gradient keeps the drift; matching SSS's needs a matching term derived per quadrature node.
  • The SSS component cap for Blender. Mip-Splatting ended at on lego, close to the provisional 300k; the full matrix should set the cap per scene from Mip-Splatting's counts.
  • Repeats. Single runs differ by up to 0.16–0.2 dB; claims at that size need several seeds.
  • Remaining matrix. 8 Blender scenes zoom-out, 9 Mip-NeRF 360 scenes zoom-in, each filter alone, several K, and the exact-ν-gradient baseline. The pilot's A100 timings do not transfer to the G4 directly.
